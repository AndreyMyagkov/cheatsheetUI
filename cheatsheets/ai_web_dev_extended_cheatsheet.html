Кто лидер по инструментарию?

  • agentic coding: Claude Code и Codex — самые зрелые премиальные агенты
  • IDE-опыт: Cursor или Windsurf — быстрый inline-редакторинг и мультимодал
  • экосистема GitHub: Copilot — меньше всего трения в корпоративном репо
  • открытость и BYOK: OpenCode — модель-агностичный harness
  • Лидер зависит от задачи: один инструмент «лучший» только на вашем репо и смеси моделей

BYOK: чужой ключ в свой инструмент

# Claude Code → Anthropic-совместимый endpoint DeepSeek
export ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
export ANTHROPIC_AUTH_TOKEN=$DEEPSEEK_API_KEY
export ANTHROPIC_DEFAULT_SONNET_MODEL=deepseek-v4-pro

# OpenCode: model в opencode.json
{ "model": "opencode/deepseek-v4.1-flash-free" }

# Codex: ~/.codex/config.toml
model = "gpt-6.2-sol"
model_provider = "openai"

важно Подписка и API-ключ — разные деньги: первая даёт лимит в сообщениях/кредитах, второй — счёт за токены. Через гейтвей можно потерять prompt caching и точные имена моделей, поэтому проверяйте /status на маленькой задаче.

Экономия токенов: рабочие приёмы

  • Короткий always-on: AGENTS.md уходит с каждым запросом — держите его конкретным
  • Progressive disclosure: модель видит только name и description скилла, полный текст — по вызову
  • План → build: отдельные агенты plan/build в OpenCode, Exit Plan Mode у Qwen
  • Subagents: изолируют контекст и возвращают краткий отчёт, а не целые файлы
  • Compact: /compact, <leader>c в OpenCode; не везде есть аналог
  • Кэш: стабильный префикс дешевле; у Gemini CLI кэш есть не для OAuth
  • Английский обычно токенизируется эффективнее — это эвристика, не цитата из docs
  • Не делайте дампы репо и логов; используйте grep/glob, @file.md, /skills
  • Дешёвая модель на батчи: Haiku / Luna / Flash / GLM Flash / DeepSeek Flash
  • Просите diff и патч, а не полную перепечатку файла

Минимум для AGENTS.md, skill и agent

AGENTS.md — один файл на проект

# AGENTS.md — читают почти все агенты
# Stack
React 19, TypeScript strict, Vitest, pnpm

# Commands
pnpm install · pnpm test · pnpm lint

# Rules
- только компоненты кита, без inline-стилей
- планировать перед правкой, ревьюить diff
- коммит только после зелёных тестов

# CLAUDE.md для Claude Code (импорт, без копипаста):
@AGENTS.md

Skill: папка с SKILL.md

# .opencode/skills/print-audit/SKILL.md
---
name: print-audit              # ≤64, lowercase
description: Проверка печати A4; use when asked to audit PDF.
---                            # description ≤1024
1. Открыть references/checklist.md
2. Запустить scripts/check_print.py FILE.pdf
3. Сообщить число страниц и проблемы

# ID в OpenCode = имя папки, а не frontmatter name
# Claude: .claude/skills/<id>/SKILL.md
# Qwen: .qwen/skills/<id> · Codex: CODEX_HOME/skills/<id>
# Devin/Windsurf: .devin/skills/<id>
# тело <5000 токенов и <500 строк — рекомендация spec

Agent: дочерняя роль со своими правами

# .opencode/agents/reviewer.md
---
description: Ревью diff без правки файлов
mode: subagent
model: anthropic/claude-sonnet-5-5
permissions:
  - action: edit
    resource: "*"
    effect: deny
---
Review the current changes. List findings with file and line.

Что когда использовать

  • AGENTS.md — правила, которые нужны в каждой сессии
  • Skill — модель выбирает сама по description
  • Slash-команда — её вызывает пользователь: /review
  • Agent — роль с моделью, правами и свежим контекстом
  • MCP — внешние действия: Jira, Figma, GitHub
  • RAG — внешние знания: ADR, API-доки, старые тикеты
  • Hook — жёсткое действие: линтер перед коммитом

правило AGENTS.md короткий — он съедает контекст всегда. Skill ленивый — грузится только когда релевантен. Не копируйте одно и то же в оба файла.

MCP: где искать и пример

  • Каталоги: registry.modelcontextprotocol.io, mcpservers.org, каталоги Atlassian / Figma / GitHub
  • Скилы: github.com/anthropics/skills, skills.sh, .opencode/skills/
  • .mcp.json хранит серверы, но не токены — токены в env
  • Права минимальные: read-only там, где хватает чтения

Один использует Claude, другой OpenCode

  • Источник правды — AGENTS.md в корне репозитория
  • Для Claude Code добавьте CLAUDE.md с строкой @AGENTS.md
  • Скилы держите в репо: .claude/skills/ и .opencode/skills/
  • .agents/skills/ читают Qwen и Windsurf/Devin, но это не универсальный стандарт
  • Если нужны оба набора — синхронизируйте скриптом, не symlink на Windows
  • Не считайте, что один файл подхватят оба: проверяйте /memory и /agent
  • Не полагайтесь на ~/.claude/ и ~/.config/opencode/ как на командные правила
  • Команды сборки и тестов — только в AGENTS.md, чтобы поведение совпадало

Минимальная структура репо

repo/
├─ AGENTS.md              # общие правила
├─ CLAUDE.md              # @AGENTS.md + Claude-only
├─ .mcp.json              # Jira, Figma, GitHub
├─ .agents/skills/        # частично Qwen/Devin
├─ .claude/skills/        # Claude Code
└─ .opencode/
   ├─ skills/
   ├─ agents/
   ├─ commands/

Проверка перед интервью

  • /context all в Claude Code — какие memory-файлы реально загрузились
  • /models и /status — активный провайдер и модель
  • Спросите агента: «какие правила проекта ты видишь?» — сверьте с AGENTS.md
  • Прогоните одну маленькую задачу до большого рефактора

безопасность Токены и ключи — только в env/secret manager. Trial-модели Nvidia и часть free-моделей собирают фидбек: не отправляйте туда приватный код или чужие макеты.

Workflow

Неизвестный проект: первый проход

// 1. беглый осмотр без правок
README → AGENTS.md → package.json → src/
pnpm test · pnpm lint · pnpm build

// 2. зафиксировать правила для агента
/init → AGENTS.md: стек, команды, стиль, табу

// 3. понять потоки
«Покажи 3 главных потока данных и где state»

// 4. только потом код
маленькая задача → plan → diff → тест → коммит

Проект с нуля

npm create vite@latest app -- --template react-ts
cd app && npm i
npm i -D vitest @testing-library/react

// сразу положить AGENTS.md
# Stack: React 19, TS strict, Vitest
# Commands: npm test / npm run lint
# Rules: план → код → тест → diff

// первая фича = план → build → тест → коммит

правило Сначала план, потом код. Ревьюьте diff, а не болтовню в чате. Тест — обязательный артефакт задачи, коммит — только после зелёных проверок.

  • Реальный репо: AGENTS.md, CLAUDE.md, .mcp.json

  • Живой цикл: план → правка → pnpm test → diff
  • Короткий skill, который реально вызывается по описанию

Частые провалы

  • Отдать агенту весь репо без AGENTS.md и надеяться «сам разберётся»
  • Принять большой diff без плана и без тестов
  • Сравнивать модели только по цене за токен
  • Хранить API-ключ в конфиге репозитория
  • Думать, что горячие клавиши одинаковы во всех инструментах
