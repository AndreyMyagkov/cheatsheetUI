# AGENTS.md — правила работы с cheat-ui

Репозиторий шпаргалок A4 на базе `css/cheat-ui.css`. Перед работой прочитайте
`README.md` и скил `cheat-ui`.

## Карта файлов

| Путь | Роль |
| --- | --- |
| `css/cheat-ui.css` | библиотека стилей: токены, компоненты, темы, печать |
| `kit.html` | витрина компонентов и палитры, переключатель тем |
| `examples/_example_cheatsheet.html` | шаблон новой шпаргалки |
| `cheatsheets/<subject>_cheatsheet.html` | готовые шпаргалки |
| `README.md` | документация |
| `.opencode/skills/` | локальные скилы OpenCode |

Git уже инициализирован. Не делайте `git init` повторно.

## Разрешённое действие

**Агент по умолчанию создаёт только новый файл `cheatsheets/<subject>_cheatsheet.html`
по запросу пользователя.** Больше ничего не меняется.

Менять шпаргалку можно, если пользователь сам просит дополнить или отредактировать

Запрещено трогать:

- `css/cheat-ui.css` и любые стили;
- `kit.html`;
- `examples/_example_cheatsheet.html`;
- `README.md`, `AGENTS.md`, `.opencode/`;
- уже существующие файлы в `cheatsheets/`.

Если нужно исправить стиль, скил или документацию — скажите пользователю,
не редактируйте сами.

## Имя файла

`<subject>_cheatsheet.html`, только латиница, нижний регистр:

- `vue_cheatsheet.html`;
- `react_cheatsheet.html`;
- `vitest_cheatsheet.html` (уже есть).

Не используйте дефис, опечатку `cheetsheet` или русские имена файлов.

## Обязательный опрос до создания

Сначала задайте вопросы, **дождитесь ответов**, и только потом пишите файл.
Скил `cheat-ui` содержит полный сценарий в `references/questionnaire.md`.

1. **Предмет и имя файла** — тема и латинский `<subject>`.
2. **Уровень** — `начальный / средний / hard / всё`.
   «Всё» означает: положить блоки всех уровней, пользователь сам удалит
   лишнее. Не «оптимизируйте» по своему усмотрению.
3. **Стек/версия/язык примеров** — JS/TS/Python, версия фреймворка, библиотека.
4. **Объём** — 2 / 3 / 4 листа или «как упакуется».
5. **Блоки и их объём** — предложите конкретное меню (установка, каркас, API,
   таблица, рецепты, конфиг, ошибки, продвинутое, отладка) и спросите,
   что включить.

Пока пользователь не ответил — файл не создаётся. Вопросы задавайте через
инструмент вопросов, а не просто списком в тексте.

## Как создавать файл

1. Скопируйте `examples/_example_cheatsheet.html` в
   `cheatsheets/<subject>_cheatsheet.html`.
2. В `<head>` уже стоит `<link rel="stylesheet" href="../css/cheat-ui.css">` —
   не меняйте его.
3. Первый лист: `.sheet.sheet--cover` с `.cover`; остальные — `.sheet` с
   `.sheet-head accent-*`. Внутри — `.columns` и `<section class="block accent-*">`.
4. Используйте только компоненты кита: `.block-title`, `.code-block`, `.list`,
   `.callout`, `.table`, `.chip`, `.kbd`, `.tok-*`. Цвет — через `.accent-*`,
   без inline-стилей и хардкода цветов.
5. Один `.sheet` = одна печатная страница. Номера `.page-number` (`1 / 4`)
   считайте по факту листов.

## Проверка печати

После создания **не запускайте** `cheat-ui-print-audit` сами. Сообщите
пользователю, что можно проверить печать командой:

```sh
python .opencode/skills/cheat-ui-print-audit/scripts/check_print.py \
  cheatsheets/<subject>_cheatsheet.html /tmp/cheatsheet.pdf
```

Скил запускается только по прямому запросу пользователя.

## Коммиты

Формат — Conventional Commits, сообщения на английском:

```
feat: add vue cheatsheet
docs: clarify cheatsheet workflow
chore: remove legacy source
```

Агент **только предлагает** сообщение коммита в конце ответа. Коммит делает
пользователь. Не выполняйте `git add` / `git commit` самостоятельно.

## Definition of done

- [ ] Заданы все 5 вопросов, получены ответы.
- [ ] Создан ровно один новый `cheatsheets/<subject>_cheatsheet.html`.
- [ ] Стили, витрина, шаблон, docs, скилы и чужие шпаргалки не тронуты.
- [ ] Путь к CSS в новом файле — `../css/cheat-ui.css`.
- [ ] Первый лист с `.sheet--cover`, номера страниц соответствуют числу листов.
- [ ] Пользователю предложена проверка печати и сообщение коммита.
