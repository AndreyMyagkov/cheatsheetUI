# Опрос перед созданием шпаргалки

Этот файл — единственный источник формулировок вопросов и меню блоков.
Агент обязан задать **все 5 вопросов** через инструмент вопросов и дождаться
ответов. Пока ответов нет, файл не создаётся.

## Принцип

Пользователь может удалить лишное из готовой шпаргалки. Агент, наоборот,
не должен заранее «урезать» контент: если выбран уровень «всё», включаются
блоки всех уровней. Задача агента — собрать материал и уложить его, а не отредактировать
по своему вкусу.

## Вопрос 1. Предмет и имя файла

Спросите:

> Какую тему сделать и как назвать файл? Имя — латиница, нижний регистр,
> по шаблону `<subject>_cheatsheet.html`.

Правила:

- `vue` → `vue_cheatsheet.html`, `react-router` → `react_router_cheatsheet.html`;
- не использовать дефис в конце и опечатку `cheetsheet`;
- если пользователь дал русское название, предложите латинский транслит
  и подтвердите его.

## Вопрос 2. Уровень

Спросите с вариантами: `начальный / средний / hard / всё`.

| Уровень | Что включать |
| --- | --- |
| начальный | установка, каркас, базовые API/методы, 1–2 ошибки, минимум кода |
| средний | начальный + конфигурация, готовые рецепты, таблица сравнений, 3–5 ошибок |
| hard | средний + продвинутые возможности, внутренности, крайние случаи, отладка |
| всё | все три набора; пользователь сам удалит лишнее |

По умолчанию, если пользователь не выбрал уровень, переспросите. Не считайте
«всё» вариантом «по умолчанию» молча.

## Вопрос 3. Стек и язык примеров

Спросите:

> Какой язык/стек и версия? На чём писать примеры — JS, TS, Python, bash?
> Есть конкретные библиотеки или версии (Vue 3, React 18, Node 20…)?

Если ответа нет, предложите дефолт для темы, но явно обозначьте его как
предположение и дождитесь подтверждения.

## Вопрос 4. Объём

Спросите: `2 листа / 3 листа / 4 листа / как упакуется`.

| Объём | Ориентир по блокам |
| --- | --- |
| 2 листа | 6–9 небольших блоков |
| 3 листа | 9–14 блоков |
| 4 листа | 12–18 блоков |
| как упакуется | считать по выбранным блокам, но назвать итоговое число листов до создания |

Один лист выдерживает ~5–7 блоков или 2–3 блока с длинным кодом. При сомнении
добавляйте лист, а не уменьшайте шрифт: стили трогать нельзя.

## Вопрос 5. Блоки и объём

Покажите меню и спросите, что включить. Можно выбрать несколько пунктов.

| Блок | Объём | Компоненты | Уровень |
| --- | --- | --- | --- |
| Установка и запуск | 5–8 строк команд | `.code-block` | начальный |
| Каркас / базовый синтаксис | 8–12 строк | `.code-block` | начальный |
| Основные API и методы | 6–10 пунктов | `.list`, `.code-block` | начальный |
| Таблица сравнений | 3–5 строк | `.table` | средний |
| Готовые рецепты | 2–4 сниппета по 6–10 строк | `.code-block`, `.callout` | средний |
| Конфигурация | 6–10 строк | `.code-block` | средний |
| Ошибки и подводные камни | 4–6 пунктов | `.list`, `.callout--warn` | средний |
| Продвинутые возможности | 2–4 блока по 5–8 строк | `.code-block`, `.list` | hard |
| Тестирование и отладка | 5–8 строк | `.code-block`, `.callout` | hard |

Если выбран уровень «всё», отметьте в меню **все** строки и скажите,
что пользователь может убрать любые из них после создания.

## После ответов

1. Кратко повторите выбранные: тему, имя файла, уровень, стек, число листов
   и список блоков.
2. Скопируйте `examples/_example_cheatsheet.html` в
   `cheatsheets/<subject>_cheatsheet.html` и соберите контент.
3. В ответе дайте путь файла, команду проверки печати и сообщение коммита
   `feat: add <subject> cheatsheet`.

Никаких изменений в стилях, витрине, шаблоне, документации, скилах и чужих
шпаргалках.
