# cheat-ui: создание новой шпаргалки

Единственная задача скила — **создать новый файл** `cheatsheets/<subject>_cheatsheet.html`
после того, как пользователь ответил на обязательные вопросы.

Перед началом прочитайте `AGENTS.md` из корня проекта и
`references/questionnaire.md` (путь относительно каталога этого скила).

## Жёсткие границы

- Не трогайте `css/cheat-ui.css`, `kit.html`, `examples/`, `README.md`,
  `AGENTS.md`, `.opencode/` и уже существующие файлы в `cheatsheets/`.
- Не меняйте стили и не добавляйте inline-стили/хардкод цветов.
- Не запускайте `cheat-ui-print-audit` после создания — только предложите
  пользователю команду проверки.
- Не делайте `git add` и `git commit`; предложите сообщение коммита текстом.

## Шаг 1. Опрос (обязательно)

До создания файла задайте **все 5 вопросов** через инструмент вопросов
и дождитесь ответов:

1. предмет и имя файла (латиница, `<subject>_cheatsheet.html`);
2. уровень: `начальный / средний / hard / всё`;
3. стек, версия и язык примеров;
4. объём: 2 / 3 / 4 листа или «как упакуется»;
5. выбор блоков и их объём из предложенного меню.

Полные формулировки, меню блоков и правила уровня — в
`references/questionnaire.md`. **Пока нет ответов — файл не создаётся.**
Если пользователь ответил «всё», включите блоки всех уровней; он сам удалит
лишнее. Не «оптимизируйте» и не вырезайте контент по своему усмотрению.

## Шаг 2. Создание файла

1. Скопируйте `examples/_example_cheatsheet.html` в
   `cheatsheets/<subject>_cheatsheet.html`.
2. В `<head>` оставьте `<link rel="stylesheet" href="../css/cheat-ui.css">`.
3. Обновите `<title>`, `.cover__eyebrow`, `.cover__title`, `.cover__subtitle`
   и чипы под выбранную тему.
4. Соберите листы по ответам:
   - первый — `.sheet.sheet--cover` с `.cover`;
   - остальные — `.sheet` с `.sheet-head accent-*`;
   - внутри — `.columns` и `<section class="block accent-*">`.
5. Наполните выбранными блоками. Используйте только компоненты кита:
   `.block-title`, `.code-block`, `.list`, `.callout`, `.table`, `.chip`,
   `.kbd`, `.tok-*`. Код подсвечивайте `<b>` для имён методов и `.tok-comment`,
   `.tok-string`, `.tok-number`, `.tok-keyword`, `.tok-builtin`.
6. Один `.sheet` = одна страница. `.page-number` (`1 / 4`) выставьте по факту.

Ориентир по ёмкости: один лист выдерживает примерно 5–7 небольших блоков
или 2–3 блока с длинным кодом. При переполнении лучше добавить лист, чем
уменьшать шрифт — стили менять нельзя.

## Шаг 3. Отчёт пользователю

Коротко перечислите:

- путь созданного файла;
- выбранные блоки и число листов;
- команду ручной проверки печати (не запускайте её сами):

```sh
python .opencode/skills/cheat-ui-print-audit/scripts/check_print.py \
  cheatsheets/<subject>_cheatsheet.html /tmp/<subject>.pdf
```

- предлагаемое сообщение коммита в Conventional Commits:

```
feat: add <subject> cheatsheet
```

## Частые ошибки

- Создать файл до ответов на опрос — не делайте этого.
- Убрать «лишние» блоки из «всё» — пользователь режет сам.
- Изменить CSS ради плотности — запрещено.
- Оставить путь `href="cheat-ui.css"` — из `cheatsheets/` нужен `../css/cheat-ui.css`.
- Забыть `.sheet--cover` на первом листе или перепутать номера страниц.
- Написать имя файла с дефисом или опечаткой `cheetsheet`.
