# Проверка печати cheat-ui

Цель: получить PDF, в котором число страниц ровно равно числу `.sheet`,
ни один блок кода/таблицы не разрезан, подвалы у нижнего края, а тёмная
тема печатается только светлым оформлением.

> Скил запускается **только по прямому запросу пользователя**. После создания
> новой шпаргалки агент не запускает его сам, а лишь предлагает команду проверки.

## 1. Рендер и отчёт

Из корня проекта запустите (`--png` — по желанию, для визуального осмотра):

```sh
python .opencode/skills/cheat-ui-print-audit/scripts/check_print.py \
  cheatsheets/vitest_cheatsheet.html /tmp/vitest.pdf --png /tmp/audit-images
```

Скрипт сам запускает Chrome с уникальным `--user-data-dir`, считает страницы
PyMuPDF, печатает для каждой страницы `top / L / R / footer`, позиции
подвалов, первую и последнюю строку контента. Если число страниц не
совпадает с числом `.sheet`, он завершится кодом 3.

Проверка темы:

```sh
python .opencode/skills/cheat-ui-print-audit/scripts/check_print.py \
  cheatsheets/vitest_cheatsheet.html /tmp/vitest-dark.pdf --theme dark
```

Ожидаемо: тот же результат по числу страниц и положению блоков; цвета
светлые, от темы остаётся только оттенок H.

## 2. Что читать в отчёте

Эталон для текущей шпаргалки: `pages: 4`, у каждой страницы `footer≈788`
(полезная область до ~813 pt при полях 10 мм). Лист 2 — самый плотный,
контент доходит примерно до 740–790 pt; листы 3–4 — до ~430–540 pt
(остаток — поля).

Тревожные признаки:

- `pages > count(.sheet)` — лишняя страница: переполнен лист или блок
  прыгнул целиком вниз.
- У страницы `top` около 0, а контент `L/R` около 10–30 — на страницу
  выехал «хвост» предыдущего листа.
- `footer` отсутствует или уехал на середину — сломалась распорка
  `.columns { min-height: 710pt }` или поток подвала.
- WARN «content overlaps the footer zone» — контент заходит под подвал.
- Последняя строка страницы обрывается посреди выражения, а первая
  следующей продолжает её — разорвался `.code-block`.

Если включён `--png`, откройте PNG всех страниц: таблицы и блоки кода
должны быть цельными, колонки — сбалансированными, подвал — у низа.

## 3. Порядок исправлений (от безопасного к рискованному)

1. **Плотность, а не разрывы.** Уплотните `.code-block` (`font-size`,
   `line-height`, `padding`), `.block-title`, `.list > li`, `.callout`,
   margins. Именно это позволило уложиться в 4 страницы без потери контента.
2. **Перенос блока между листами.** Если один лист переполнен, а соседний
   пуст, переместите целый `<section class="block…">` в соседний лист —
   только если это не ломает смысловую группировку (например, конфиг
   теста логичнее рядом с компонентными тестами).
3. **Разрывы.** Не добавляйте `break-inside: avoid` на `.block`: высокий
   блок уедет вниз и оставит пустоту. Оставьте код и таблицы неразрывными,
   `.callout { break-before: avoid }` — чтобы выноска оставалась при коде.
4. **Только в крайнем случае** меняйте `@page` поля или геометрию листа.
   Помните: геометрия не должна зависеть от темы.

## 4. Грабли

- Chrome headless конфликтует на одном профиле; скрипт использует свой
  `TemporaryDirectory`, не запускайте параллельные рендеры вручную без
  `--user-data-dir`.
- `counter(page)` и `counter(pages)` в печати Chrome дают `0 / 0`; номер
  в подвале — ручной текст `1 / 4`.
- В print-слое темы перебиваются через `html, html[data-theme]`; чтобы
  проверить тёмную тему, достаточно `data-theme="dark"` на `<html>` —
  скрипт сделает временную копию рядом с исходником и удалит её.
- Отладочные PNG/PDF держите вне каталога проекта (например, в
  `%TEMP%\opencode`), если их не просили оставить.

## Definition of done

- [ ] `pages == count(.sheet)` для paper и dark.
- [ ] Подвалы у нижнего края, номер совпадает с номером листа.
- [ ] Код и таблицы не разрезаны; выноски при своих блоках.
- [ ] Оригинальный контент не изменён (кроме опечаток).
